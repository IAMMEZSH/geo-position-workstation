## 每条闸门长什么样

```js
push('单次反算耗时（预热后 30 次均值 < 40 ms）', inv_ms < 40, inv_ms.toFixed(2) + ' ms/次');
```

`{name, pass, detail}` 三元组；`detail` 必须是**能拿去对答案的数字**，不是 `ok`。
界面 ⑪ 展开通过项明细时直接把 `detail` 打出来，所以「绿」是可读的，不是黑盒。

## 一个计时闸门今天被抓出来

`GEOGEO` 原来有一条 `单次反算耗时 < 12 ms`，5 次循环、冷启动直接计时，而且**判定和展示各跑一遍**。
在浏览器里它一直绿；今天把它放进 Node 沙箱跑，第一次就报 `13.00 ms/次` 判失败——那不是公式错，
是 JIT 冷启动噪声，而且展示的数字跟被测的数字根本不是同一次。

改成：先预热 30 次，再测 30 次的均值，只测一遍，判定与展示同一个数，阈值放宽到 40 ms
（这条闸门的作用是「没把算法写崩」，不是基准测试）。连跑三次 537 门 / 0 失败。

> 顺带的教训：**能被环境抖出来的闸门就不该存在**。写绝对耗时阈值时，先问自己
> 「它在慢机器的冷进程里会不会红」；会，就改成预热 + 宽阈值，或者改成相对比较。

## 界面级验证（内核看不见的那一类）

内核全绿不等于界面能用。这个项目已经踩过两次「全绿但画面是坏的」：

1. 离线陆域一个像素都没画（数据嵌套少钻一层，1374 块全被跳过）。
2. 标题行和标签页被地图盖住点不动（窄屏断点下 `.mapwrap` 退成 `position: static`，
   Leaflet 的 400~1000 z-index 逃到整页最前）。

所以 ⑪ 的环境表里多了「矢量陆域」一行，断言挂图块数与 `base` 图层对象数；
排查层叠问题用 `document.elementFromPoint()` 直接问「这个坐标上最上面的元素是谁」，
修完应当是 `HEADER.topbar` / `BUTTON.tab`，而不是 `CANVAS.leaflet-zoom-animated`。

## 第三个看不见故障的地方：`.gitignore` 误吞交付文件

写仓库忽略规则时顺手加了一行 `*.log`（本意是桥接日志）。但本项目要分发的样例里有一份
`示例数据/NMEA语句示例.log` —— 它被静默排除，页面照跑、内核自检照绿，只有别人 `git clone`
之后才会发现少了一个文件，而那时已经看不出少了什么。

现在改成只忽略根目录那一个（`/桥接服务.log`），并由 `check-package.py` 反向检查：
把 `.gitignore` 的规则套到 `示例数据/ app/ vendor/ docs/ images/ tests/` 的真实文件上，
任何命中都算失败（`app/_build/` 是开发期产物，白名单放行）。同理，README 与 docs 里每条
本地图片/文件链接都对着磁盘核一遍——GitHub 首页的裂图不会触发任何运行时错误。

## 第四个看不见故障的地方：同一个端口上跑了两个桥接

整理仓库时顺手 `netstat` 了一眼，发现 `127.0.0.1:8765` 上有**两个**进程同时 LISTENING。
原因是 `HTTPServer.allow_reuse_address = 1`，而 Windows 的 `SO_REUSEADDR` 允许第二个进程绑到
正在监听的端口（POSIX 上会直接 `EADDRINUSE`，所以这个坑只在 Windows 出现）。后果不是报错，
而是连接被随机分走：改了 `server.py` 重启，页面刷新的行为却来自上一个还没退的旧进程——
看起来像「我的修改没生效」。

修法是在绑定之前先对目标端口发一次回环 connect：已有人监听就直接退出，并打印换端口的命令。
当场验证（桌面副本，一个桥接已在监听）：

```
首个桥接：ok=True bind=127.0.0.1:8765 loopback_only=True
重复启动退出码： 2
重复启动输出： 启动被拒绝：127.0.0.1:8765 已经有一个桥接服务在监听……
端口上监听者数量： 1
```

这类问题内核自检永远看不见——它测的是算得对不对，不是机器上有几个服务在抢同一个端口。
所以补了两条 `--selftest` 门（`server.py --selftest` 从 78 项涨到 80 项），其中拒绝那条
用桩函数替掉真实探测，不依赖端口上到底有没有人。
